# Gateway lease authority v3

Status: implementation awaiting controlled build, migration activation and real-role acceptance. Source parsing is not cryptographic or product acceptance.

Gateway is the only holder of the platform Ed25519 signing seed. Its private configuration file is selected by `AI_PLATFORM_GATEWAY_ED25519_KEYRING_FILE` and contains `active_key_id`, `signing_seed_hex` and a `verification` public keyring. Runtime and capability Worker receive only `AI_PLATFORM_LEASE_VERIFY_KEYRING_FILE` (or the mutually exclusive JSON form). Public keyring schema is `gateway-verification-keys/v2`; each key has `key_id`, `public_key_hex`, `not_before_ms`, `not_after_ms`, and `revoked`. One or two unique keys are admitted. Consumer loaders reject the Gateway private configuration variable and unknown fields.

`AI_PLATFORM_LEASE_TRUST_MODE=verify_only` rejects legacy HMAC calls and consumer HMAC secrets. `transition` explicitly permits legacy verification only until `AI_PLATFORM_LEASE_HMAC_ACCEPT_UNTIL_MS`, which must be in the future and within 24 hours. An unconfigured deployment retains its legacy HMAC contract. Installing public verification keys defaults consumers to verify-only. Missing keys, mismatched signatures, purpose, scope, revision or expired authority fail closed; asymmetric verification never falls back after a failed signature.

Gateway signs model leases and launch envelopes with separate purposes. Managed capability ceilings use `capability-ceiling` / `turn-capability-ceiling/v3` and the real Runtime thread. Genuine SDK ceilings use `sdk-capability-ceiling` / `sdk-capability-ceiling/v3` and an empty thread field, explicitly representing absence of Codex lineage. Their real SDK run, immutable snapshot and shared assistant run remain authoritative. Purpose/schema/thread-domain mismatches are rejected. No signing seed or open witness is placed in the SDK bridge response.

Each ceiling fixes tenant/user/session, run, snapshot, revision, allowed capability IDs, descriptor hashes/effects and maximum per-call TTL. Runtime holds only a scoped attenuation witness, restricts it to one exact unsigned lease and descriptor, and seals it before delivery. Worker verifies the Gateway root and every attenuation block plus seal, compares the snapshot to its actual authority binding and still performs its existing durable reservation and owner/fence checks. Delivered sealed proofs cannot mint another call, change arguments, tool, tenant or expiry, or remove a restriction. Delegation requires a proper subset. This is a repository-specific chained Ed25519 proof format, not a claim of Biscuit interoperability.

Open witnesses are private bearer authority: snapshots and execution owner context contain only the public signed root. The witness table is Gateway INSERT/SELECT and Runtime SELECT only, with no Worker/Knowledge/PUBLIC access. Witness insertion and run/snapshot issuance commit together. The inactive SQL proposal preserves two real foreign keys via generated managed/SDK snapshot columns and checks each purpose against the real run engine, scope, immutable public envelope and revision. The SDK path uses `issue_sdk_execution` and `assert_sdk_execution`; it creates no managed thread. Runtime reads the SDK witness only for the current native owner/fence and unexpired non-revoked SDK authority. V3 missing-table/configuration errors fail closed; legacy unconfigured paths do not query this table.
