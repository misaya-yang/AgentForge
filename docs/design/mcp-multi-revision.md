# Restricted dual-revision MCP integration

Source implemented, not activated or accepted against real reference servers. The default remains `2025-11-25`. Explicit record `protocol_version`/`protocol`, or the operator-only `AI_PLATFORM_MCP_PROTOCOL_REVISION` fallback, selects exactly `2025-11-25` or `2026-07-28`; unknown revisions fail closed. The SDK retains `connect` with its legacy default and adds `connect_with_revision`. No request header selects a trusted broker revision.

The production discovery factory, read-only invocation broker and SDK HTTP/stdio request codec use the same foundation-owned revision module. The legacy branch keeps initialize/initialized and existing session handling. The modern branch calls server/discover, checks supportedVersions, emits protocolVersion/clientInfo/clientCapabilities in every request's namespaced _meta, mirrors MCP-Protocol-Version/Mcp-Method/Mcp-Name and does not initialize or pin a session. A modern session header is rejected. Known modern version/header/capability errors are surfaced after matching JSON-RPC identity, never used to retry a tool or silently initialize legacy. Cache keys and discovery receipts carry the selected revision; metadata URL changes also change cache identity.

Modern tool parameter headers follow the official x-mcp-header schema extension. Only statically reachable properties with string, boolean or JavaScript-safe integer types may be mirrored. Names must be unique case-insensitively and valid HTTP tokens. Invalid definitions are excluded from modern discovery; actual calls use the approved schema snapshot, not a newly fetched schema. Non-ASCII/control/space-padded/sentinel-looking values use the specified Base64 sentinel. Resource/header bounds are local safety policy. Unsupported result patterns are rejected; no MRTR, sampling or elicitation capability is advertised. This restricted slice does not claim full modern-protocol conformance.

OAuth protected-resource metadata is fetched by bounded unauthenticated GET over the existing HTTPS public-address DNS pin, with no redirect, proxy, issuer fetch or token POST. Configured same-origin metadata URLs and path/root well-known candidates are supported; a 401 Bearer resource_metadata challenge is parsed and used without replaying the original POST. Cross-origin metadata requires a separately admitted resolver/pin and is rejected in this slice. The document resource must exactly match configured resource, authorization_servers must be nonempty HTTPS issuers, and header bearer transport must be supported. Modern OAuth requires resource/audience/credential-audience agreement. A resource-indicator parameter builder is provided; OAuth authorization/token exchange remains in the credential-owning flow and is not implemented by this MCP broker. The existing registry query now actually supplies its already-stored oauth_metadata_url and transport fields.

Gateway still runs HTTP MCP only. A stdio/non-HTTP server record fails with MCP_STDIO_SANDBOX_REQUIRED before network/spawn. Existing explicitly configured SDK-local stdio behavior remains; it is not Gateway sandbox admission. Capability Worker sandbox execution/conformance is still a prerequisite for enabling platform stdio.

Added source tests exercise both actual factory session state machines, modern HTTP SDK discover/list/call loopback, metadata/header mirroring, Base64 encoding, invalid schema annotations, exact resource/issuer metadata, challenge parsing, cache separation, session confusion, foreign response IDs and downgrade/no-replay rejection. The implementation writer ran syntax parsing and whitespace checks only, not Cargo, Docker or servers. Native compilation, real TLS metadata/challenge fixtures, OAuth resource-indicator exchange through the credential owner, both reference-server revisions and CW stdio isolation remain release gates.
