# Runtime and Worker OTLP telemetry (U-RT-09 Ph1)

Implementation is awaiting controlled compilation, tests and collector acceptance. No live OTLP result is claimed here.

Export is disabled unless `AI_PLATFORM_OTEL_ENABLED=true`; `OTEL_SDK_DISABLED=true` overrides enablement. An enabled process requires an explicit `OTEL_EXPORTER_OTLP_ENDPOINT` HTTP(S) base URL. Credentials, query and fragment in that URL are rejected. Signals use explicit HTTP/protobuf and `/v1/traces`, `/v1/metrics`, `/v1/logs`. No discovery, exporter initialization or telemetry network call occurs on the default disabled path. Standard configured collector authentication headers are transport configuration, not captured request data.

Both platform-owned services use explicit OTel 0.32.0 / SDK 0.32.1 dependencies; the upstream harness retains its own pinned dependencies unchanged. Exporters use explicit blocking HTTP clients on dedicated SDK batch threads, a three-second request timeout, no redirects, queues of 1024 and batches of 128 for traces/logs. The metrics reader periodically exports bounded SDK instruments with authenticated tenant/model dimensions. Tenant cardinality follows actual tenant activity; it is not a fixed global cardinality. Exporter initialization failures degrade to disabled export with a fixed `OTEL_INIT_FAILED` diagnostic. Initialization and graceful flush run outside the request executor; each signal has a four-second shutdown bound. Export failures increment `agentforge.otel.export.failures` by signal and produce rate-limited local `OTEL_EXPORT_FAILED` diagnostics, without formatting the endpoint, transport error or response. SDK queue saturation diagnostics remain local. Business execution never waits for export.

GenAI conventions are pinned to **1.37.0**, schema URL `https://opentelemetry.io/schemas/1.37.0`. `invoke_agent` spans start at managed admission and end on actual kernel stop/error/abort. `chat` spans start immediately before actual Codex model generation and terminate exactly once on response Completed, error, send failure or stream drop. Warmup is excluded. Response streams are passed through unmodified. Only nonnegative provider input/output token counts are recorded in the `gen_ai.client.token.usage` histogram, with `gen_ai.token.type`, sanitized `gen_ai.request.model`, and a local authenticated tenant observation. The first text-delta boundary records `gen_ai.client.operation.time_to_first_chunk` exactly once per model request; no response items are inspected. Capability HTTP creation and actual Worker execution have `execute_tool` spans. Durable approval admission/decision boundaries emit `approval_wait` spans. Latencies use seconds in `gen_ai.client.operation.duration`.

Gateway must forward W3C `traceparent` and `tracestate` on private Runtime launch, SDK capability and model proxy boundaries. Runtime and Worker admit canonical version-00 lowercase nonzero trace/span IDs and flags 00/01, parse tracestate with the OTel W3C parser, and discard orphan tracestate when traceparent is invalid. Runtime model metadata carries the accepted context through the upstream model-request extension seam. Worker delivery uses the Runtime client span as parent; downstream Worker HTTP calls continue the actual execution span. Correlation/tenant headers retain existing business handling but are not OTLP attributes. After process restart no prior context is fabricated: a recovered execution without request context starts a fresh trace.

The exporter receives fixed service name, semconv version, operation, outcome, duration, token type/count and W3C context only. Actor, session, thread, run, request and execution identifiers stay out of exported attributes. Authenticated tenant IDs use only `agentforge.tenant.id=sha256:<full SHA256 of exact tenant ID>`; native service accounting uses the same mapping. Tenant IDs are the existing case-sensitive varchar identifiers, not assumed UUIDs. Raw tenant names stay out of exports and model metadata. Sanitized model identifiers and opaque tenant dimensions annotate model spans and usage/duration metrics. Gateway emits actual durable settled USD through the shared native accounting telemetry, rather than Runtime estimating a price. Prompt, code, tool name/arguments, model-visible metadata, authorization, provider URLs and exception text are never copied. Existing application fmt logging is not bridged into OTLP. There is no content-capture switch. Turn/approval observations are process-local and bounded at 1024; durable database state remains the execution authority. Shutdown drains incomplete turn observations before exporter flush.

## Verification to run in the controlled source build

Run affected Runtime/Worker library tests, including telemetry/export tests, trace_context tests and model stream tests. Source tests cover valid/invalid propagation, redacted collector config, fixed span attributes, remote parent IDs, exactly one terminal span, bounded-batch shutdown flush, safe exporter failure counting, content stream transparency and cancellation dropping upstream once. Run upstream core model_request tests after materializing the two small seam overlays. Shared manifests and lockfiles are coordinated by the primary agent, not edited by the telemetry writer.

Product acceptance remains open: start an isolated authorized local collector, send one real Gateway model/tool request, inspect the complete same-trace hierarchy and all three signal payloads; repeat with collector unavailable, queue saturation, cancellation and process shutdown. Inspect raw export payloads for the absence of seeded prompt/code/credentials/actor values. Verify exporter-off emits no collector traffic and preserves prior request outcomes. SDK and real-provider workflows remain separate product checks.
