# 04｜Agent Studio 与评测

依据：[现状E08、E09](01-current-state.md)。Studio、已发布Agent页面和Eval都有实现；本轮不把页面存在或旧候选单例运行等同于当前版本全流程通过。

## M05：Agent Studio 与已发布 Agent

### 用户与目标

Agent构建者希望把重复任务固化为可维护的配置；最终使用者希望得到与发布说明一致的能力。目标是让“编辑了什么、保存了什么、预览了什么、发布了什么”始终可区分。

主流程：创建Agent → 明确任务/输入/成功标准 → 配置模型、工具、知识和记忆 → 保存草稿 → 隔离预览 → 保存问题为用例 → 比较候选 → 发布固定版本 → 在已发布入口使用 → 查看反馈 → 更新或回滚。

### 发布规则建议

基线采用“保存草稿 → 明确验证 → 人工发布”。仅改变外观文案的版本与改变工具、知识、权限的版本，其验证要求应不同，但不允许用文案分类绕过真实能力变化。首次公开、扩大受众或新增外发工具需要可见确认。

Eval自动阻断应在 EV-03/04/05 能提供可解释结果后启用；在此之前保持已有发布规则，并显式显示“尚未完成对应验证”，不新增一个永远无法解除的假门禁。具体发布条件由[决策D04](07-delivery-and-acceptance.md)冻结。

人工例外不得豁免配置有效性、身份/权限、明确副作用状态或受影响流程尚未关闭的P0。只有经定义为可例外的质量/性能目标，才允许负责人记录理由、适用受众、有效期和回退条件后有限发布；不修改历史评分，不把例外发布标成全部门禁通过。现有更严格规则继续保留。

## M06：Eval、Trace 与知识评测

2026-09-29：固定拒答或其他精确输出合同可显式选择
`{"type":"output_equals","value":"The selected knowledge does not specify that."}`。
该断言去除首尾空白后比较完整正文，区分真正拒答与只引用预期短语的无关回复；
已有 `output_contains` 保持子串语义。更换断言需产生新数据集修订/manifest，旧运行评分不改写。

真实候选、Trace 重评分和发布验证使用同一完整数据集清单计算哈希，
包含数据集修订、用例正文、断言、审核状态、split 和 Trace/span 来源。
旧运行保留原清单身份；关联发布必须重新运行取得一致的清单，不能放宽哈希比对。

公开有效期在运行时快照中统一为 UTC ISO 时间。同一时刻的 `Z`、`+00:00`
及其他时区表示产生相同快照身份；实际改变有效期仍会使旧发布验证失效。

### 用户与目标

构建者与质量负责人需要发现问题、复现问题，并判断候选是否值得替换当前版本。Eval不是把各种分数放在一张表，而是让用户能解释“哪个任务、在哪个版本、因为什么失败”。

主流程：导入样本或从Trace/知识QA提取 → 审核样本 → 固定数据集与候选配置 → 运行 → 区分执行故障与质量失败 → 比较 → 决定发布/不发布 → 后续反馈进入下一轮。

### 最小可交付例子

构建一个使用合成知识库的内部Agent。用例包含正确事实、无答案、权限撤销、工具拒绝和一次可恢复失败。候选A和B都跑同一组固定用例；对比页能指出真实退化，发布页保留所选版本及验证依据。此流程通过才证明Studio与Eval衔接完成。

## 2026-10-12 原生 Eval 裁判失败重试入口

原生运行结果保留「模型执行成功、质量未评分」的裁判失败事实，不把它改成普通零分
或模型执行失败。结果中的可选 `retry_available` 是只读提示：所有 attempt 已终态，
每条 attempt 均通过共享的重放安全检查，且没有取消、待协调或副作用未知状态，才
提供选择入口。混合 attempt 不得由第一条安全失败掩盖另一条不安全失败。

Web 的失败筛选包含模型已完成但评分未完成的样本；仅在原生提示明确允许时，新增
此类样本的重试入口。旧 Python/旧原生结果可省略该字段，保留原有行为/执行失败的
选择规则，不猜测未评分样本可以重试。提示不替代 POST 对当前权限、KB 来源和持久
副作用账本的核验；提交仍可能被拒绝。POST 复用同一全 attempt 资格判断，收紧此前
仅检查第一条失败 attempt 的路径，并以一次租户范围内的批量查询检查所有 attempt
的持久副作用身份，避免只验证复制到新运行的源 attempt。

重试仍经过已有确认：使用冻结输入创建独立的单次 `live_candidate` 运行，会重新
执行模型并可能计费，不是只对旧 Trace 重评分。幂等键、旧运行结果、质量分母和比较
可归因规则不变。此增量的离线函数/组件验证不能证明真实 provider、数据库并发、
浏览器或取消中断全链路已通过。

## 2026-10-12 Trace 诊断定位与导出身份

EV-07 / OB-02 / OB-04 的 Trace 入口以 URL 中明确的 `trace_id` 和 `family`
作为同一个目标，不再要求目标先出现在当前 50 条列表、筛选结果或第一页中。
只有没有明确目标时才自动展示第一条；目标不存在或当前身份无权读取时，保留该目标
的错误，不替换成另一条运行。手动选行写回 URL；运行结果跨 family 打开时一次写入
完整目标，并保留其他来源查询参数。浏览器前进、后退与重返链接按 URL 恢复目标。
线程视图中明确指定但未读到的 turn 也不由其他 turn 代替。手动刷新同时重读列表及
当前明确目标的详情，不触发执行或重放；没有目标时不发起空 ID 的详情请求。

导出仍调用原有服务端授权及脱敏接口，不扩展返回字段或权限。展示的安全导出预览绑定
请求时的 Trace、family、导航和非凭据认证会话标识；切换目标、账户、会话或有效权限后，
旧预览立即不可见，迟到的旧请求不能替换新目标的预览。浏览器 POP 恢复旧历史 key 时，
使用本次访问的新标识，不恢复前次访问的导出或接纳其未完成请求；离开页面卸载后，
旧请求也不再展示成功或错误通知。Trace 列表、详情、线程与诊断
总览缓存以同一临时会话标识隔离，缓存键中不存放 token；后端租户、用户和 family 检查
保持不变。此项没有增加原始 payload、隐藏推理、凭据或私有资料的导出。

本增量的页面闭包、路由与异步响应双重测试属于离线函数证据；不替代浏览器、真实
权限撤销、数据库、服务端脱敏全链路或生产诊断验收。

## 2026-10-14 API 渠道 Token 操作恢复

Token 管理将加载失败与真正空列表分开，读取失败时隐藏旧状态。创建、轮换、撤销
共用同步操作锁，持续到只读回查结束；权限或身份变更后不接受旧响应，也不展示旧密钥。

## 2026-10-14 评测取消与失败重试恢复

取消、重试确认固定原运行、实验与当前访问身份；切换页面、运行、账号或权限后，
旧确认不可提交，迟到响应不可更新新页面。确认与提交共用同步操作锁；取消回包
按服务端实际状态显示，完成赢过取消时不宣称已取消。运行详情必须独立读取，

### Agent governance deletion receipt and explicit continuation (2026-10-15)

The Agent analytics governance page retains a current-view deletion observation:
confirmed Agent, scope, optional subject, request key, and the last valid receipt.
Confirmation freezes those values. Lost or malformed responses remain unknown;
repeat confirmation reuses the same identity instead of creating a new cleanup
inventory. Numeric reported counts, genuine zero, receipt status and attempts
remain visible; internal policy, inventory and execution-plan objects are not
rendered as counts. A later analytics/audit refresh failure does not erase an
accepted receipt.

Continuation is explicitly a destructive POST, never a read-only refresh. Both
backends may execute pending/failed work under the original durable request and
current authorization/legal-hold checks. The UI sends nothing automatically and
requires another confirmation before continuation. A terminal receipt can be
cleared only by the explicit new-operation control before preparing another
request. Failed receipts with a completion timestamp are not offered continuation.
A pending or failed observation does not imply earlier effects were rolled back.

The view and read-cache identities include the current authentication scope.
Retained actions, confirmations and late replies retire on identity, Agent or view
changes; duplicate confirmation/submission is single-flight. Deletion controls
still require current owner authority and absence of legal hold. No server
permissions, retention policy, credential behavior, deletion implementation or
inventory semantics are changed. The receipt is not persisted across navigation
or reload; the user can copy its identifiers before leaving. Controlled deferred
UI/transport fixtures do not establish real storage deletion, backend concurrency,
browser acceptance or full Agent governance acceptance.
