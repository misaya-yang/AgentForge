## 1. 产品判断

当前已经有较完整的产品骨架和可用核心流程。2026-09-22 的本地验收证明了对话、刷新恢复、工具审批执行/拒绝、知识检索及引用、修正后的会话冷恢复；这些能力应保留。其余页面、接口或测试文件存在，只能证明已有实现，不能直接推导出每条用户流程都已验收。

下一阶段的产品目标是：**用户在每个现有模块都能完成一项明确工作，知道当前状态，遇到问题能采取有效下一步，离开再回来也不丢进度。** 每个模块都覆盖创建/配置、正常使用、异常处理、后续管理，不以页面数量、代码量或测试数量定义完善程度。

本轮规划的重点是已有功能的完整性、一致性、可理解性和跨模块衔接。继续复用 Codex Rust 核心及现有平台能力；只有实际产品合同不能满足时，才评估必要适配。订阅支付、市场营销、完整桌面应用、分布式高可用和新检索算法不进入本次功能完善基线。

## 5. 优先级和需求类型

- **P0**：核心任务无法完成，或状态/权限/副作用被误表达；修复并验收后才能发布受影响流程。
- **P1**：让现有主要功能独立可用，补齐异常、管理和跨模块衔接；属于本次功能完善基线。
- **P2**：提升效率或增加使用方式；不阻塞 P0/P1 收口。

表中的类型：**修正**=有具体源码或历史实机问题；**补齐**=已有基础需要连通或完善；**验证**=实现存在但尚缺足够当前版本证据；**新增**=明确的新产品能力。验证项先重现、确认，已满足就登记通过，不能默认重写。

P0 是发布优先级，不自动表示本轮发现了可利用漏洞。权限相关静态疑点先用隔离用例核实；不得把待验证风险写成已经发生的数据泄漏。

## 6. 全局产品规则

1. **状态一致。** 页面、历史、任务详情与可公开诊断来自同一事实；运行失败不能显示成功、空白正常完成或永久加载。
2. **操作可预期。** 保存、测试、运行、发布分别说明作用对象和生效时间；双击和重连不能重复执行副作用。
3. **有权限才有能力。** 厂商支持、管理员已配置、用户被授权、当前会话可调用是四个不同事实；不可用时说明缺少的前提。
4. **错误有下一步。** 显示安全的原因、影响和可执行动作；对未知副作用不提供“自动重试即可”的误导建议。
5. **数据有归属。** 文档、会话、产物、Trace、用量均按当前授权访问；公开链接不是绕过授权的备用入口。
6. **已有成果可恢复。** 刷新、断网和进程重启后，保存过的输入、已完成结果和任务身份仍可定位。
7. **界面只承诺实际能力。** 不支持的模型选项、格式、平台和权限档位禁用并解释；占位组件不计为已交付功能。

## 7. 规划完成与功能完成是两件事

本轮完成标准：所有现有入口有模块归属；每个模块说明用户、现状、问题、需求和可判定验收；优先级、依赖、边界及待决定事项可供后续拆分开发；通过文档读者检查和链接/结构检查。

后续功能完成标准：相应需求在指定候选版本上有正常、失败、权限及恢复证据，用户连续流程通过，重要缺陷关闭。PRD、原型、接口存在或单元测试通过都不能独立代替功能验收。

既有架构/升级 PRD 保留为历史设计与技术约束。本 PRD 聚焦产品功能，不重新激活已结束的 runbook，也不把其未完成的公开发行矩阵偷偷纳入每个功能包。
