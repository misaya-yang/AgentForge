## Genuine production gaps found during code comparison

- Missing release idempotency header returned 400 instead of source428: fixed narrowly in publish/rollback route branches.
- Snapshot construction was mutating every non-platform high-risk binding to require confirmation, contrary to source configuration preservation: removed that mutation. Runtime-side enforcement remains unchanged.
- Copy endpoint was viewer-accessible and reused generic creation rather than source owner-only atomic copy/audit/default naming: fixed with native AgentRepository::copy and route wiring, retaining source transaction, copy audit, default name/slug and stripped bindings.

## Explicit remaining evidence / functionality boundaries

Downstream runtime resume/SSE/attachment scenarios are not proven by Studio pure or repository tests. Full authenticated analytics/deletion HTTP scenarios and concurrent dataset/model race variants are incomplete test coverage, not automatically evidence that corresponding production functions are absent. Current native service files must be compared before labeling a behavior unimplemented. Source-only private mock calls/import arrangements are retired where no external behavior is lost. No authorization checks, gate thresholds or unknown-side-effect rejection are relaxed to obtain passing tests.

## Historical assistant harness references

The current engineering tree does not ship the earlier `thinking_policy.py`, `tool_selector.py`, `subagent_manager.py` implementations or the referenced historical thinking/selector/provider test files. Their names remain in the preexisting `assistant-general-agent-harness` runbook. They are stale historical references, not newly missing source to reconstruct. Current source launch policy lives in `src/services/assistant_entry/launch_resolution.py` and current native entry/model policy in `migration_agent/{entry,control,model,runtime_contract}.rs`.

Current native runbook targets with concrete retained assertions are `runtime_control_plane` (Responses tool controls, native multi-agent configuration, subagent lifecycle projection and immutable platform configuration), `runtime_capability_contract` (authorized readonly capability discovery), and `runtime_v2_turn_contract` (Thread/Turn/Item observation invariants). These must not be described as direct coverage of the removed historical thinking/provider test suites. There are currently no dedicated gateway tests directly invoking `apply_reasoning_wire`, `responses_to_messages`, or `builtin_launch`; this is an explicit coverage limitation, not permission to replace the current runtime model boundary with obsolete code.

Current shipped assistant-entry comparison found and fixed another real identity discrepancy: builtin native model parameters included null-valued temperature/max_tokens/thinking_mode when omitted by the caller, while source launch resolution omits these keys. The native control-plane construction now omits unset options, preserving source model/spec fingerprint identity. Empty developer-instructions use the source generic fallback; builtin knowledge retrieval defaults now preserve source empty/zero fallback semantics. This is a targeted port correction, not a reconstruction of retired thinking/tool-selector code.

## Client packaging portability correction

`platform-client-packaging` now supplies the packaging-only CLI without linking Unix server-operation modules from `platform-tools`. Both tools reuse the same `packaging.rs` implementation. Unix process-group smoke remains; Windows uses bounded pipe polling and a Job Object, with archive metadata checks retained and Unix filesystem chmod gated. Source material paths normalize separators, and the portable launcher canonicalizes output containment with Windows drive prefixes. The SDK-worker lane owns workflow routing; root owns workspace registration/build. Windows/macOS packaging execution is not claimed by Linux compilation.
