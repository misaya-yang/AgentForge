### 已确认的真实阻塞与正在实施的修复

- **J03 Runtime 进程重启：**当前 Rust Runtime 启动会将旧待审批 run 持久化为 `cancelled/APPROVAL_ORPHANED`；审批等待器是进程内 oneshot，重启后无法在同一 run 上安全继续。已把这个受控原因独立投影为“服务重启中断”，保留 run ID/正文和人工下一步，不自动重发工具。此修正不满足 PRD 所需的同 run 续执行；需要独立的持久 turn/checkpoint 与审批重绑定合同。
- **J05 附件：**实查上传返回 `/uploads/...`，而 Worker 的 `read_attachment` 仅接受会话归属 `art_*`，且旧动态工具参数与 Worker 目录不一致。已实现上传到会话 artifact 的稳定绑定、V1/V2 权限校验、单一静态目录描述符及 Runtime 每次工具调用的本轮引用检查，Docker 内 Rust 编译和真实附件读取尚在进行。受控跨用户/跨会话、模型不支持图片等回归已过。
- **AS-09 图片：**旧附件工具只返回图片尺寸。已增加受当前会话授权、2 MiB/张上限的临时图片输入，并在 Runtime 将其交给现有模型多模态输入合同；仍须 Docker 编译与真实视觉模型验收，不能仅凭代码声称通过。
- **构建环境：**首次本地 Runtime Docker 构建被宿主机 `127.0.0.1:7890` 代理传入容器而阻断 apt。移除该构建命令的代理环境后，镜像源已可连接，Docker 内编译正在执行；没有在宿主运行 Cargo。

### 最后一轮真实服务与故障定位

- **受控故障定位：**本地附件上传成功但 turn 创建返回 422；安全分类日志定位到本地流式上传写在未加 `dev/` 前缀的路径，而下载会加该前缀。仅对已核对租户/用户/文件名的本地附件兼容旧布局；独立 reviewer 还指出上传服务未初始化时的第三条旧本地目录，已补受限回退。三个针对性回归覆盖服务未初始化、前缀错位和旧本地目录。此处早期的 422 在 run 创建前，未执行工具。
- **真实工具链路：**首次绑定后 Worker 用补了 `max_chars` 默认值的参数核对 Runtime 对原始 JSON 的租约哈希，产生 `attachment argument hash mismatch`；模型当轮如实报无法读取。Worker 已改为先核对原始 JSON，再规范化发往 Gateway。重建当前 Rust Runtime/Worker 镜像后重新上传，浏览器真实 Qwen 回答 `cobalt / 7319`，工具活动包含 `read_attachment`；刷新保留正文、终态与活动，accepted turn POST 未增加。此前失败轮仍保留在 E2E 会话中作为诊断，不将其写成通过。
- **最终代码部署后：**追加 reviewer 提出的旧本地目录回退后再次 `make hot-update ARGS="--gateway"`；内置浏览器只读刷新仍显示已保存的 `cobalt / 7319` 与“已完成”，未重新发送。
