**Date:** 2026-08-12
**Primary repository:** `/Users/yang/projects/AI--Platfform`
**Purpose:** close every locally observed Hermes/OpenClaw capability with an implementation, adoption milestone, or explicit rejection; define the result-level benchmark needed to decide parity.
**Current acceptance state:** achieved for the requested minimum result cohort on 2026-08-13: AI--Platfform completed 6/8 tasks (75%), versus Hermes 5/8 and OpenClaw 5/8 (62.5% each), with zero infrastructure errors. The stronger three-repeat E5 release cohort remains a separately labelled milestone and is not claimed here.

This document is a decision ledger and executable benchmark contract. It is not a claim that the planned work ran, that an old report is still green, or that a source-level mechanism completed a real enterprise task.

## 1. Non-negotiable product boundary

1. `AgentLoop` remains the only execution plane. API, Responses, streaming, non-streaming, benchmark adapters, scheduled work, subagents, and future local-device control must enter the same canonical loop and `AssistantExecutionGateway`; a thin client is allowed, a second agent engine is not.
2. Multi-tenant isolation, dataset authorization, capability allowlists, approval binding, sandboxing, and redaction are hard constraints. A single-user convenience from Hermes or OpenClaw is rejected if it weakens any one of them.
3. “Completed” means the externally inspected deliverable and state satisfy the task oracle. Non-empty text, a claimed success, a tool call, or an internal score is not completion.
4. Historical tests, checked-in observations, static source reachability, and local help output remain separate evidence classes. Only commands actually executed against the pinned snapshot may appear as current run evidence.

## 7. Fair three-way execution protocol

### 7.1 Cohort and environment

1. B0 manifest pins each source commit/tree, dependency lock, runtime/image digest, launch command, adapter digest, model/provider ID, sampling parameters, task packet digest, oracle digest, OS/architecture, and secret-presence booleans. Any drift aborts the suite.
2. Use the same provider/model/context limit/tool-call mode for all three systems. If no one model is natively supported by all three, the cohort is invalid for a single ranking; run separate explicitly named common-model cohorts and do not average them together.
3. Inputs come from frozen local packets or deterministic replay services. A task may contain authentic public material, but changing live search results cannot determine the winner.
4. Every trial starts with a fresh workspace, session, tenant/profile namespace, browser profile, mock service state, and random hidden mutation generated from one signed seed shared across systems.

### 7.2 Adapter neutrality

1. The task prompt specifies outcome, constraints, available business services, and required approvals; it never requires `spawn_subagent`, a particular agent ID, exact internal tool names, reasoning text, or a specific delegation topology.
2. The neutral adapter maps benchmark services to each system's native supported mechanism and emits a common receipt: messages, tool lifecycle, approvals, clarification, artifacts, external state snapshots, usage, terminal status, runtime fingerprint, and redaction manifest. It may translate protocol, not add missing reasoning, security, retries, or task logic.
3. AI--Platfform's adapter must call the authenticated Gateway/public Assistant ingress and therefore Gateway → canonical `AgentLoop`; it may not instantiate a hidden loop, directly call tools, inject approval success, or read internal answers.
4. Hermes/OpenClaw adapters receive the same service credentials and isolated profiles. If a native system cannot express a required capability, the trial fails rather than the adapter implementing the capability on its behalf.

### 7.3 Budgets and human events

1. Normal tasks receive the same 20-minute wall clock, model-token ceiling, tool-call ceiling, parallelism ceiling, and external-service quota. BMT-11 receives 45 minutes. Values are pinned in each scenario contract and may only be reduced equally before a cohort starts.
2. Approval/clarification scripts are precommitted and replayed identically: approve, deny, expire, and changed-argument variants. The model cannot see future decisions.
3. Rate-limit/provider faults are injected by the same deterministic schedule. One system cannot receive a silent retry allowance unavailable to the others; native retries count against the common budget.
4. No operator may rescue a trial, edit its answer, rerun only a favorable system, or discard an unfavorable receipt. Infrastructure-invalid trials are rerun for all three with the same seed and recorded invalidation reason.

### 7.4 Independent adjudication

1. Collector records raw protocol and external state only. It cannot calculate pass/fail. Deterministic oracle runs in a separate process/key boundary and verifies task packet, adapter, raw receipt, artifacts, state diffs, and runtime fingerprint hashes.
2. Coding, arithmetic, API state, file structure, tenant/approval, cancellation, duplication, and leak checks are automated hard gates. Research/legal/finance/incident synthesis additionally uses two blinded reviewers who see anonymized outputs in randomized order; disagreement goes to a third reviewer. Reviewers cannot waive a hard gate.
3. A trial passes only when all mandatory result and safety gates pass. A useful memo with an unauthorized read/write is failed; a perfectly safe empty/non-actionable answer is also failed.
4. Completion rate is exact macro trial rate: `passed_trials / 36` for each system, with per-task `passed_trials / 3` also reported. No partial credit enters the acceptance comparison. Confidence intervals, latency, cost, and reviewer subscores are diagnostics, not substitutes for completion.
5. Goal acceptance requires `AI_rate >= Hermes_rate` and `AI_rate >= OpenClaw_rate`, plus zero AI enterprise hard-gate violations. All 108 trial dispositions, including infrastructure invalidations, remain in the report.

### 7.5 Receipts and publication

1. Raw events and state snapshots are content-addressed, mode-restricted, redacted, independently HMAC/signature-sealed, and bound to suite nonce, trial seed, cohort manifest, task/oracle/adapter digests, and startup fingerprint.
2. Artifact or state success is established by the external oracle, never by assistant prose or a candidate-provided score.
3. Publish per-trial terminal reason, result gates, security gates, token/tool/time/cost usage, adapter warnings, and evidence tier. Sensitive content stays in controlled storage; the public report contains digests and bounded excerpts only.
4. A benchmark report is E5 only after every expected trial is present, independently verified, and the cohort manifest matches. Missing receipts fail closed.
