# CPython 3.14 curated wheels and tenant grants

This directory freezes the optional data stack for Linux amd64/arm64. The full `requirements-*.lock` and `tooling-*.lock` are requirements-format hash locks generated by uv 0.11.19 against CPython 3.14 and manylinux 2.40 using only binary distributions and the official PyPI index. They are not an invented universal `uv.lock`. No local Python 3.14 installation was downloaded to generate them.

`amd64/` and `arm64/` contain the exact selected wheel URL/hash inputs and one requirements-format lock per distribution. The selected official PyPI file hashes were checked against the uv resolver hashes, wheel tags, target architecture and transitive runtime requirements. `wheel-manifest-*.json` records those immutable URLs/hashes/sizes. `catalog-*.json` records the exact installed distributions and dependency closure. `lock-receipt.json` explicitly records that **wheel bytes were not downloaded or verified during implementation**; image builds must verify them with `--require-hashes` and run the real smoke/escape tests. Metadata agreement is not binary or image acceptance.

The curated top-level stack is NumPy, pandas, SciPy, matplotlib, Pillow and openpyxl. The build-only uv wheel is pinned to 0.11.19 and is never copied to either final image. Nothing installs packages at runtime. Each distribution lives under `/opt/agentforge/python-packages/<canonical-distribution-name>` outside the stdlib tree. The final sandbox removes pip/ensurepip and global site-packages. Installation uses a downloaded hash-checked wheelhouse, then offline `uv pip install --no-index --no-deps --require-hashes` for each exact package. Source distributions/build backends cannot run.

A tenant package policy is public deployment configuration, selected with the sandbox daemon's `--package-policy`. The matching architecture's `tenant-policy-*.example.json` demonstrates the schema and exact catalog SHA256. Replace only its example tenant map with authorized tenant IDs; do not use the example as a platform-wide grant. Unknown tenants, omitted policy and tenants with an empty list have stdlib only. A grant includes its exact pinned transitive dependencies (e.g. granting pandas includes NumPy); no tool argument or submitted source selects an installation, version, URL or package directory.

At service startup the policy/catalog are loaded as an immutable snapshot, catalog bytes/architecture/CPython minor are checked, and configured package directories must exist and be read-only. Each execution adds only that tenant's selected dependency roots to Landlock read rules and the isolated interpreter's controlled sys.path. All other optional package roots stay unreadable, even if user code guesses their paths or changes sys.path. `-I -S -B` stays enabled; no `.pth` or normal site initialization runs. The small trusted runpy bootstrap preserves the submitted script bytes, `__file__`, future imports and script argv. Package caches/TMPDIR are scoped to the ephemeral workspace, and BLAS/OpenMP/NumExpr thread counts are fixed to one to retain the existing no-thread/fork boundary.

To refresh the resolution deliberately, use the existing uv binary and an external cache, explicit official index and `--no-python-downloads`. For each target platform:

```sh
uv pip compile requirements.in --python-version 3.14 --python-platform x86_64-manylinux_2_40 --only-binary :all: --generate-hashes --default-index https://pypi.org/simple --no-header --no-annotate --no-config --system-certs --no-python-downloads -o requirements-amd64.lock
uv pip compile requirements.in --python-version 3.14 --python-platform aarch64-manylinux_2_40 --only-binary :all: --generate-hashes --default-index https://pypi.org/simple --no-header --no-annotate --no-config --system-certs --no-python-downloads -o requirements-arm64.lock
```

After any refresh, regenerate exact wheel selections and catalogs from official PyPI metadata, check every selected hash belongs to the resolver lock, evaluate runtime dependency markers for Linux CPython 3.14, update policy catalog hashes, then run the real two-architecture image verification. Do not hand-invent hashes or keep a stale catalog after changing a lock.
